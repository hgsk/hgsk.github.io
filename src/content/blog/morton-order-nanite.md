## きっかけ

UE5用のNanite方式ガウシアンスプラッティングレンダラー [NanoGaussianSplatting](https://github.com/TimChen1383/NanoGaussianSplatting) を読んでいて、最初に立った疑問は「なぜ Morton コード順にソートするのか」だった。

Mortonコードとは、XY（3DならXYZ）座標のビットをインターリーブした整数。別名 Z-order curve と呼ばれる。

このソート、一見「単に配列を並べ替えただけ」とも見える。しかし実は、インポート時のクラスタ構築と毎フレームの深度ソートという、全く別の場所で効いている。しかも Nanite 本体も同じ構造。この共通構造を掘り下げてみる。

## Mortonコードの性質: 1次元の整列が2次元の局所性になる

Morton曲線は再帰Z字を描く自己相似の空間填充曲線。座標のビットを交互にはさむことで、**コードの数値順 ≈ 空間的な近さ** になる。

- コードが近い2点は、たいてい空間でも近い
- コードの連続区間は、空間的には1個の矩形領域（箱）に対応する
- 区間の共有プレフィックスが長いほど箱は小さい。短いほど大きい

つまり「ソート済み配列の区間」がそのまま「空間の箱」に対応する。この対応が本質で、以降のすべてはこの1行から出てくる。

## この性質が支える2つの処理

### 1. クラスタ構築（Nanite的階層）

NanoGaussianSplattingでは、インポート時にスプラットを Morton コード順にソートして、小さなリーフクラスタにまとめ、それをマージして親レベルを作る。各クラスタにはバウンディングスフィアとLODエラー値を持たせる。

なぜ Morton 順が要るのか。**並べ替え前の配列順は空間に無関係**だから。ランダム順の配列の「隣の要素」は空間の隣とは限らない。区間=箱の対応が崩れ、親子関係が空間的包含にならない。

Morton順に並べれば、配列の連続区間 = 空間の箱になるので:

- 先頭から128個で区切る → 各チャンクは空間的にコンパクトな箱になる
- 箱の親子関係が空間的な包含関係になる
- 「このクラスタは画面のどこに映るか」をバウンディングスフィア1個で判定できる
- 親のエラー値 ≥ 子のエラー値の単調性も保てる

これが Nanite と同じ発想。Nanite はメッシュを空間分割でクラスタ化し、親クラスタへの縮約（グラフ収縮）で階層を積む。**空間的にコンパクトなクラスタでないと、カリングもLOD選択も機能しない**。

### 2. 深度ソート（毎フレーム）

ガウシアン・スプラッティングの透明描画は、奥から手前の順にブレンドする必要がある。つまり毎フレーム、全スプラットを視線方向の深度でソートする。NanoGaussianSplattingでは GPU radix sort（8bit×4パス）でこれをやる。CPU介入なし。

ここで Morton が再登場する。ソート済み配列はすでに空間のZ字曲線順に並んでいる。視線方向から見ると、曲線の走査順は「ほぼ奥→手前」に沿っている。深度キーは完全なソートをせずとも、この準備された順序の近傍でほぼ整列済みになる。radix sort は整列済みに近い入力で高速に収束するし、ソートの前に「空間チャンク単位の大まかな深度並べ替え」を1回挟むだけで、各チャンク内の順序はもうほぼ正しい。

つまり Morton 順は **毎フレームのソートコストを下げる下地** にもなっている。深度の順序は空間の順序と強く相関するからだ。

加えて、空間的に近いスプラットがメモリ上も近いことで、クラスタ単位の処理（カリング、LOD選択、間接描画の引数生成）がすべてキャッシュフレンドリーになる。GPUの coalesced アクセスに乗る。

### 3. おまけ: 圧縮

圧縮パスでも Morton が出てくる。スプラットのスケールを Morton スイズルテクスチャに格納するのだが、これも「近いコード = 近い空間 = 似たスケール」という局所性があれば圧縮効率が上がる、という理屈だ。

## Nanite との対応

Nanite のレンダリングパイプラインと見比べる。

| NanoGaussianSplatting | Nanite |
|---|---|
| スプラットを Morton 順でソート | 頂点/三角形を空間分割でクラスタ化 |
| リーフクラスタ → マージで親レベル | グラフ収縮で親クラスタを生成 |
| バウンディングスフィア + LODエラー値 | 同左（クラスタごとに誤差メトリック） |
| クラスタ単位のフラスタルカリング | クラスタ単位のカリング |
| スクリーンスペースエラーでLOD選択 | 同左 |
| GPU radix sort | （不透明なので深度ソート不要） |
| 間接ディスパッチでCPU読み戻しゼロ | 同左（GPU-driven） |

共通しているのは「**空間でコンパクトなクラスタの階層 + エラー値 + GPU主導のカリング/LOD選択**」という構造。そしてその土台が「配列区間 = 空間の箱」を成立させる Morton 順ソートだ。

違いも明確で、ガウシアン・スプラッティングは半透明の順序依存ブレンドが必要なので、Nanite にはない深度ソートが毎フレーム入る。ここでも Morton が下地として効いている、というのが面白いところ。

## まとめ

- Mortonコード順ソートは「並べ替え」ではなく、**1次元配列の区間を2次元/3次元空間の箱に対応させる宣言**である
- これにより (1) 区切り方だけで空間コンパクトなクラスタが作れ、(2) 毎フレームの深度ソートが整列済み近傍から始められる
- Nanite（メッシュ用）と NanoGaussianSplatting（スプラット用）は、対象が違っても「Morton順 → クラスタ階層 → クラスタ単位カリング/LOD → GPU主導描画」という同一の構造をしている
- 差分は深度ソートの有無。半透明ブレンドの順序依存性がガウシアン・スプラッティング特有の難しさで、そこにも Morton が下地として効いている
